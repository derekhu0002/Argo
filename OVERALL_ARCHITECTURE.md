# ARGO Implementation Architecture Contract

## Root rules

1. Production dependencies point from the unified MCP gateway to the intent-query boundary and from that boundary to canonical graph persistence; production code never depends on `tests/`.
2. `getSystemArchitecture` remains the single public reading interface. An omitted `query` preserves the legacy complete canonical response; an explicit `query` selects purpose-aware behavior.
3. Canonical JSON is authoritative. Semantic retrieval may derive context but cannot replace, mutate, or silently truncate a required full snapshot.
4. Test Harness code may invoke public production boundaries and read approved fixtures; explicit entrypoints use Harness methods and do not expose MCP, filesystem, or process plumbing.
5. Explicit entrypoints and critical guardrails listed in the implementation handoff are frozen during Coding/Repair.
6. The production Graph RAG path is Node.js plus the Neo4j JavaScript driver. Python runtimes, external Graph RAG frameworks, and the Neo4j GenAI Plugin are not required production dependencies.
7. Neo4j and embedding-provider credentials enter only through external secure configuration. Missing credentials block production startup or query delivery; direct literals, logical/nullish/ternary fallbacks, and credential-tainted Cypher query/parameter transport are prohibited.
8. Index delivery is denied until an explicit qualification names the embedding provider, model identity, model version, and dimensions. Missing fields and implicit model defaults are blocking errors.
9. Mounted acceptance evidence does not itself authorize Coding scope. Only `codingTargets` and `taskExecutionPlan` in the approved handoff authorize implementation; TS-08 remains out of scope unless a later handoff explicitly includes it.
10. Slice completion and global intent delivery are distinct. A handoff may accept its approved explicit entrypoints and guardrails while the full runner keeps a global intent element `not_delivered`; only committed mounted evidence, runner records, and runner-owned `deliveryStatus` may support that attribution.
11. Live embedding delivery uses explicit opt-in Node.js HTTPS from `alibaba-cloud-model-studio-openai-compatible-cn-beijing` at `https://llm-clids9mqc5o1mbvb.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`, model `qwen3.7-text-embedding`, qualification version `qualification-2026-07-25`, and explicitly supplied dimensions `1024`. Offline fakes cannot count as live evidence.
12. The only secret keys are `QWEN_KEY` and `ARGO_NEO4J_DATABASE_PASSWORD`. Each may come only from its direct process environment variable or the unique repository-relative `.argo/.env`, with process precedence; differing dual sources fail closed and matching duplicates may use process.
13. Live provider evidence becomes index-write eligible only after exact qualification and a finite 1024-value response. Provider errors, unapproved identity, omitted model or dimensions, non-finite values, and dimension mismatch produce zero writes to the controlled Neo4j test instance.
14. Live HTTP proof is owned by the frozen test transport, not by a production boolean or evidence label. The Harness observes the actual request target/body/count and raw response, then correlates them with gate output and persisted evidence.
15. Before reading `.argo/.env`, configuration must prove the exact path is ignored, untracked, regular, non-reparse, and protected by verifiable Windows ACLs without broad-principal read access. Root/alternate/tracked files, CLI/literal/default/fallback sources, duplicate keys, unknown secret keys, and unsafe or unverifiable state block before fetch, Neo4j connection, or writes.
16. Neither approved secret may enter logs, errors, Cypher, graph state, failure records, snapshots, or artifacts. `QWEN_KEY` never enters Neo4j; `ARGO_NEO4J_DATABASE_PASSWORD` is consumed only by the driver authentication layer.
17. The Argo harness initializer loads only the repository-relative `.argo/.env` into `process.env` before projection/runtime checks, without reading root or alternate env files or printing secret-bearing diagnostics. Canonical Neo4j projection configuration uses only `ARGO_NEO4J_DATABASE_URL`, `ARGO_NEO4J_DATABASE_USERNAME`, and `ARGO_NEO4J_DATABASE_PASSWORD`; legacy `ARGO_NEO4J_URI`, `ARGO_NEO4J_USERNAME`, and `ARGO_NEO4J_PASSWORD` aliases fail closed before connection or write side effects.
18. W3 index delivery is not complete until threshold-all seed correctness passes before ANN comparison, every successful canonical mutation advances affected-record index evidence or leaves the index non-Aligned, unaligned pure semantic queries are rejected while canonical reads remain available, and TS-09 proves the Node adapter generation/persistence path through `generateAffectedEmbeddings()`.
19. W3.1 live mutation-vector delivery is not complete until one successful `applySystemArchitectureMutation` write call automatically invokes the embedding lifecycle from its actual `touchedElementIds`, `touchedRelationshipIds`, and `touchedViewIds`, returns `embeddingLifecycle` and `alignment` in the MCP mutation response, the real approved Qwen adapter generates finite 1024-dimensional vectors, Neo4j vector-index evidence is queryable for those touched records, and Aligned is set only after that queryability check passes. Harness-created lifecycle execution, expected-touched-record substitution, and offline/fake evidence are never accepted as live W3.1 delivery evidence.
20. W4 seed retrieval delivery is scoped only to relevance-discovery seeds: Element, ArchitectureRelationship, and View are separately observable channels, each channel owns an independent threshold gate, every candidate meeting that channel gate is returned, zero-result outcomes are valid, and graph closure, traversal expansion, neighborhood closure, downstream graph completion, and global cross-channel ranking remain outside Coding scope.
21. W5 deterministic purpose closure and dispatch preserves five independent purpose categories. Four ordinary semantic categories—intent-decision, implementation-design, coding-repair, and audit—begin after W4 seeds and require named parameterized Cypher closure policies with bound parameters plus ArchiMate relationship source/target semantics. Free-generated Cypher, Agent identity, text similarity, arbitrary traversal depth, and connected-component expansion cannot decide mandatory closure. The fifth category, graph-tidy, requires no semantic closure policy id; with or without anchors it performs zero semantic operations and returns the canonical full snapshot.
22. W6 structural closure begins after W5 purpose-policy range selection and is complete only when semantic results expose governing canonical version evidence equal to the legacy graph version, every returned relationship has source/target ids plus both same-version endpoint Elements or explicit structural errors, the named target View is returned while named overlapping Views are absent unless independently matched or explicitly requested, matched Views return complete metadata, parent viewpoint, exact member/relationship object sets, and endpoints, and every returned object has exactly one ordered first-inclusion reason plus non-overwriting supplementary reasons, policy id, policy parameters/anchors, and index/version evidence.
23. W7 business acceptance is the final release gate before whole delivery. It is complete only when the approved five-purpose business benchmark proves non-empty mandatory key seed fixtures, 100% key seed recall by intersection between mandatory seeds and actual recall observations, non-empty expected closure fixtures, 100% expected closure correctness from actual closure observations, explicitly recorded non-negative unrelated forced-hit evidence, zero forced hits for unrelated queries, and recorded precision evidence inside `[0, 1]` for every purpose. Missing actual observations, wrong same-count recall ids, non-empty missing key seed evidence, closure correctness below 100%, positive unrelated forced hits, missing required benchmark fixtures, empty or incomplete benchmarks, missing or negative unrelated-hit evidence, and precision outside `[0, 1]` are blocking failures. Precision is evidence for later capacity governance, not a substitute threshold for recall or closure. Whole delivery remains blocked until W2-W6 are accepted and the W7 DT-18 benchmark passes.
24. DT-19 capacity evidence begins after real DT-18 quality evidence and remains evidence-only. It is complete only when explicit phase-1 `observedResultIds` or equivalent result ids and measured precision are preserved from actual quality observations for every declared purpose, with no closure fallback; any provided result cardinality must match the result ID count and cardinality mismatch must block. Missing quality evidence or missing result evidence blocks explicitly, while cap, budget, pagination, truncation, continuation, top-k, token-budget, result-limit, and capacity-policy decisions remain absent. DT-19 does not authorize capacity governance implementation or a release rule.
25. WP-P1 production semantic persistence is a separate durable path from live-E2E evidence. Production composition must use concrete `createProductionSemanticNeo4jAdapter()` and `createProductionSemanticCheckpointStore()` boundaries over the externally configured durable driver; production records use stable canonical identity with complete channel, canonical/content/index, provider/model/model-version/dimensions, and vector metadata; changed records upsert and tombstones delete. The exact store surface is `upsertRecords`, `deleteTombstones`, `readRecords`, and `close`; production `runId`, cleanup, clear, reset, truncate, or runId-delete behavior is prohibited.
26. WP-P1 full backfill is reachable only through explicit `backfillSystemArchitectureSemanticProjection` → `runSemanticBackfill(request)` composition after `explicitOptIn === true` and structural projection completion for the same canonical version. Missing opt-in, structural-version mismatch, external configuration, or provider qualification blocks before provider, projection, checkpoint, or index side effects. Backfill independently enumerates every Element, ArchitectureRelationship, and View in bounded checkpointed batches, isolates failures, independently proves resume by observing no repeated provider/upsert identities, reruns idempotently, performs no fake canonical mutation trigger, and marks Aligned only after all three channels complete.
27. Canonical JSON remains authoritative throughout WP-P1. Neo4j and durable checkpoints remain subordinate projection/index state; deterministic acceptance may record the raw driver below production adapters but may not replace either production adapter with an in-memory test store. Existing live-E2E runId cleanup stays test-only and unchanged.
28. WP-P2 replaces the synthetic default semantic path with one uninjected production composition. Approved external-source resolution must directly read and attribute every required embedding-profile, Neo4j, and provider-secret key from raw process or protected `.argo/.env` operations before readiness; zero-read success is forbidden. Production-semantic-query must also directly inspect all three legacy Neo4j alias keys. Missing, unsafe, conflicting, legacy-only, mixed valid-canonical-plus-any-legacy-alias, literal, test/default, fallback, alias, or indirect credential sources reject before readiness, provider, driver, or vector side effects. Legacy inspection is mandatory, but legacy values may never be attributed, selected, normalized, returned, or used downstream. A Harness may supply raw source behavior and metadata adapters but never ready-made environment credentials or normalized configuration.
29. After credential resolution and before query embedding or retrieval, the composition reads persistent readiness and rejects `SemanticIndexPending`, partial, stale, failed, unknown, explicit content-version mismatch, explicit index-version mismatch, or canonical/channel mismatch with the exact observed state, canonical/content/index versions, missing channels, mismatched channels, and `fullSnapshotFallback: false`. `createDefaultSemanticRetrieval(dependencies).readReadiness()` is the narrow public read-only form of this same gate: it shares the exact private composition/query/normalization/evaluation path with `retrieve()`, returns only the safe readiness envelope, and performs no provider/vector work. One total operation ledger must prove readiness precedes provider execution and every vector query. Only complete aligned Element, ArchitectureRelationship, and View evidence may proceed.
30. WP-P2 query retrieval uses the qualified externally credentialed provider and the exact persistent Neo4j Vector Indexes `argo_production_semantic_element_vector`, `argo_production_semantic_relationship_vector`, and `argo_production_semantic_view_vector`. Element, ArchitectureRelationship, and View are queried independently with parameterized `db.index.vector.queryNodes($indexName, $topK, $vector)` Cypher and expanding top-k/window evidence: each request correlates its exact index and raw provider vector, and each response records offset, window size, returned count, continuation, and exhaustion. Qualifying peers beyond the initial window must be returned. A valid all-zero result still requires readiness, one embedding, and one independently exhausted query sequence for every channel. Fixed top-k may optimize a window but cannot define correctness.
31. Retrieved seeds feed an exact parameterized purpose policy and declared ArchiMate source/target direction. Results must prove endpoint source/target objects and governing versions; the entire selected View metadata, viewpoint binding, parent viewpoint, ordered versioned member objects, and versioned relationship endpoint objects; exclusion of overlapping Views unless independently matched or explicitly requested; exactly one ordered first-inclusion provenance record for every returned object plus supplementary reasons; and matching canonical/content/index versions.
32. The WP-P2 default semantic composition does not admit approved-test profiles, synthetic empty seeds, caller- or Harness-injected semantic retrieval boundaries, production test credentials, silent full-snapshot fallback, manual `deliveryStatus` edits, or content/anchor-based routing to a deterministic test runtime. Ordinary semantic queries containing legacy control words or explicit anchors still pass through external credential resolution, persistent readiness, embedding, and vector retrieval. Production semantic-query credential resolution uses an explicit non-E2E use case with direct approved process or protected canonical-file attribution; it requires no live-provider or mutation-E2E opt-in and still rejects test/default, legacy, fallback, conflicting, unsafe, or untrusted sources. Only omitted-query and graph-tidy calls remain exact canonical full-snapshot bypasses; every graph-tidy request bypasses credentials, readiness, provider, and vector work regardless of anchors. SP-05/WP-P3 operator CLI, documentation, and release work remain outside this boundary.
33. WP-P3 adds one Production Semantic Operator Journey composition over accepted WP-P1/WP-P2 public boundaries. It sequences workspace initialization, canonical structural projection, approved external configuration, semantic backfill, explicit persistent readiness verification, and semantic query without reimplementing persistence, retrieval, readiness, qualification, or credential policy. Direct and CLI explicit backfill preserve the caller's `explicitOptIn` value exactly; automatic consent derives only inside opted-in start orchestration after approved configuration. A successful explicit readiness operation records a non-secret, repository-local attestation bound to canonical/content/index versions, channel diagnostics, canonical graph digest, and integrity digest. A later process or MCP call must present this recorded authorization through the operator; query without it has zero readiness/provider/vector effects. With an attestation, query may re-read the accepted WP-P2 public readiness envelope only to compare exact bound versions and invalidate stale evidence before semantic retrieval; this cannot create authorization or replace the prior explicit readiness operation. Init, backfill, canonical mutation, graph digest drift, or readiness/version mismatch clears the attestation. System and unified MCP semantic queries flow through the operator, while no-argument snapshots and graph-tidy remain unchanged bypasses. CLI and MCP wires emit one whitelisted structured redacted error envelope without stacks; package backfill never pre-injects consent. TypeChecker/flow guards protect all provenance and lifecycle rules. Canonical JSON, exact snapshots, accepted WP-P1/WP-P2 behavior, and runner-owned `deliveryStatus` remain protected.

## Stable architecture elements

| Stable element | Path | Responsibility | Public boundary |
| --- | --- | --- | --- |
| Unified MCP Gateway | `.argo/scripts/argo-mcp-server.js` | Expose one governed tool surface and delegate intent-query work inward. | `callTool(name, args)` and MCP stdio tools |
| Intent Architecture Query Boundary | `.argo/scripts/systemarchitecture-mcp-server.js` | Preserve no-argument reads, validate explicit query purpose, dispatch full-snapshot or semantic-query behavior, and route declared W5 purpose categories without using caller identity as scope. | `getSystemArchitecture` |
| Production Graph RAG Boundary | `.argo/scripts/graph-rag/` | Compose external configuration, embedding qualification, Neo4j-native retrieval, canonical-authority enforcement, W4 independent semantic seed release, W5 deterministic purpose-policy closure, W6 endpoint/View/provenance structural result completion, W7 business quality benchmark, DT-19 capacity evidence recording, and delivery sequence gates, exact threshold-all seed selection, all-mutation index lifecycle evidence, alignment gating, the explicitly opted-in approved-provider evidence gate, and the W3.1 automatic mutation-triggered live-vector lifecycle without optional runtime coupling. | `createProductionGraphRagRuntime(dependencies)`, `selectThresholdAllSeeds(request)`, `closePurposePolicyScope(request)` including W6 structural evidence, `evaluatePhase1QualityBenchmark(request)`, `evaluateCapacityEvidence(request)`, `evaluateDeliverySequence(request)`, `generateAffectedEmbeddings(input)`, `executeApprovedEmbedding(input)`, and `createMutationEmbeddingVectorLifecycle(dependencies)` consumed by `applySystemArchitectureMutation` |
| Production Semantic Persistence Boundary | `.argo/scripts/graph-rag/semantic-persistence/` | Own the separate durable production semantic projection, concrete Neo4j projection/checkpoint adapters, and explicit bounded, resumable, idempotent three-channel backfill after structural projection. | `createProductionSemanticNeo4jAdapter(dependencies)`, `createProductionSemanticCheckpointStore(dependencies)`, `createProductionSemanticProjectionStore(dependencies)`, and `createProductionSemanticBackfill(dependencies).execute({ explicitOptIn })` |
| Default Semantic Retrieval Composition | `.argo/scripts/graph-rag/defaultSemanticRetrieval.js` | Own externally configured query embedding, persistent readiness, independent three-channel Neo4j Vector Index retrieval, and delegation into deterministic closure and canonical completion for the uninjected MCP path. | `createDefaultSemanticRetrieval(dependencies)` returning `retrieve(request)` and read-only `readReadiness()` over one shared private readiness path; module-owned raw transport/driver test composition |
| Production Semantic Operator Journey | `.argo/scripts/graph-rag/semanticOperatorJourney.js` | Compose the fresh-project operator sequence over existing initialization, structural projection, approved configuration, backfill, readiness, query, and snapshot boundaries; own only sequencing, operator-safe outcomes, and command guidance. | `createProductionSemanticOperatorJourney(dependencies)` returning `startNewProject(request)`, `runExplicitBackfill(request)`, `verifyReadiness(request)`, `query(request)`, and `readFullSnapshot()` |
| Canonical Intent Graph | `design/KG/SystemArchitecture.json` | Remain the authoritative source for Elements, Relationships, Views, and memberships. | Workspace-relative canonical graph path |
| Query Acceptance Boundary | `tests/` | Own business-readable Harness, explicit entrypoints, and implementation guardrails. | Frozen Node.js entry scripts |
