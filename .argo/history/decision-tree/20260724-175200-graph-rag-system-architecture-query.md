# Graph RAG System Architecture Query Decision Tree

## Decision context

- Session: `graph-rag-system-architecture-query`
- Decision timestamp: `2026-07-24T17:52:00+08:00`
- Problem: `getSystemArchitecture` currently returns the complete intent graph. Future graph growth may exhaust Agent context, so the accepted direction is a backward-compatible Graph RAG query mode that retrieves semantically relevant graph content and then applies deterministic graph closure.
- Selected Architecture Viewpoint: `Application Usage Viewpoint`
- Stakeholder concern: downstream Agents must obtain sufficient, coherent, version-consistent intent context without losing the complete-snapshot capability required by graph mutation and audit workflows.
- Modeling purpose: deciding and handoff preparation.
- View placement rationale: the query capability explains how Agent consumers use the intent-architecture service and therefore belongs under the existing `CapabilityRealizationViewpoint` anchor. Acceptance and delivery sequencing evidence belongs under `AcceptanceDeliveryViewpoint`. Any affected View must use the repository-required viewpoint binding description.
- Scope boundary: phase 1 establishes compatibility, semantic correctness, graph closure, index consistency, and quality gates. Token budget, pagination, result caps, and truncation strategy are explicitly deferred.

## Horizontal concern boundaries

1. Backward-compatible reading: DT-01, DT-02, DT-12.
2. Query request and purpose governance: DT-03, DT-07.
3. Semantic seed retrieval: DT-04, DT-05.
4. Deterministic graph closure: DT-06, DT-08 through DT-14.
5. Explainability and traceability: DT-15.
6. Embedding lifecycle and version consistency: DT-16, DT-17.
7. Quality and capacity governance: DT-18, DT-19.

These concerns can evolve independently provided their declared vertical contracts remain stable. In particular, retrieval quality can improve without changing closure semantics, and embedding mechanisms can change without weakening canonical-version consistency.

3. Index alignment or explicit semantic-query rejection.
4. Request-mode and purpose validation.
5. Independent Element, Relationship, and View seed retrieval.
6. Type-specific relevance thresholds.
7. Purpose-policy graph expansion.
8. Relationship endpoint closure.
9. Complete-View closure without implicit View cascade.
10. First-inclusion provenance and version evidence.
11. Benchmark quality-gate evaluation.
