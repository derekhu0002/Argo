# ARGO vs OpenSpec vs SUPERPOWER vs ECC

## 1. 文档目的

本文面向产品、研发管理、架构和 AI 工程团队，提供四种方案的统一介绍与横向比较，帮助在不同业务阶段做出更合适的落地选择。

对比对象：
- ARGO
- OpenSpec
- SUPERPOWER
- ECC

## 2. 四种方案简介

### 2.1 ARGO

ARGO 是一套面向 AI Coding 的阶段化交付方法论，核心是将需求处理拆分为意图设计、实现设计、编码修复、双层验收与返工闭环。它强调结构化交接物、架构契约和可执行校验，目标是让复杂需求的交付过程可追溯、可验证、可回归。

一句话定位：面向高确定性交付的架构治理工作流。

### 2.2 OpenSpec

OpenSpec 是一套轻量、迭代式的规格驱动框架，围绕 proposal/specs/design/tasks 等工件组织开发活动。其核心理念是 action-based（动作驱动）而非 phase-locked（阶段锁定），支持在工件之间灵活往返，强调低摩擦和跨工具兼容。

一句话定位：面向快速协作的轻量规格层。

### 2.3 SUPERPOWER

SUPERPOWER 是以技能自动触发为核心的开发方法体系，强调 brainstorming、planning、subagent-driven-development、test-driven-development、code review、branch finish 等工程动作的标准化执行。它更偏向“把优秀工程习惯流程化并自动执行”。

一句话定位：面向高效率执行的技能驱动开发操作流。

### 2.4 ECC

ECC（Everything Claude Code / ECC harness）是跨多个 agent harness 的工程操作系统型方案，提供大规模 agents、skills、commands、hooks、rules，以及会话管理、持续学习、自动化循环和安全相关能力。其优势在于覆盖广、扩展快、跨平台一致。

一句话定位：面向跨平台、多语言、多场景的 AI 工程操作系统。

## 3. 核心比较（总览）

| 维度 | ARGO | OpenSpec | SUPERPOWER | ECC |
|---|---|---|---|---|
| 核心目标 | 确定性交付与架构一致性 | 轻量规格协作与迭代 | 开发效率与工程习惯自动化 | 跨平台 AI 工程全栈能力 |
| 流程风格 | 强阶段、强门禁、强闭环 | 流式动作、低阶段锁定 | 技能触发驱动的工程流水线 | 命令与技能密集型操作系统 |
| 约束强度 | 高 | 中低 | 中 | 中高（可配置） |
| 上手成本 | 高 | 低 | 中 | 中高 |
| 可追溯性 | 强 | 中 | 中 | 中高 |
| 自动化执行深度 | 中高 | 中 | 高 | 高 |
| 架构治理能力 | 强 | 中 | 中 | 中高 |
| 适合规模 | 中大型、复杂系统 | 小中型到中大型 | 小中型到中大型 | 中大型、多团队、多技术栈 |

## 4. 各方案优缺点

### 4.1 ARGO

优点：
- 意图到实现到编码的链路清晰，偏差可被及时发现。
- 双层验收与返工闭环明确，适合高风险交付。
- 交接物结构化，降低上下文丢失导致的返工。

不足：
- 流程较重，小需求可能存在过度工程化。
- 对团队流程纪律要求高。

### 4.2 OpenSpec

优点：
- 上手快，流程轻，适合快速落地。
- 工件清晰，便于团队沟通与协作。
- 可定制 schema/context/rules，灵活性高。

不足：
- 治理强度相对有限，复杂场景下易出现“规格与实现漂移”。
- 更依赖团队自行补齐严格验收机制。

### 4.3 SUPERPOWER

优点：
- 工程动作流程化，执行效率高。
- 子代理驱动、TDD、评审等实践连接紧密。
- 对“减少 agent 跑偏”有直接帮助。

不足：
- 对超复杂架构场景的契约级治理通常不足。
- 若缺少上层治理，可能偏执行而弱一致性控制。

### 4.4 ECC

优点：
- 跨 harness、跨语言、跨场景支持广。
- agents/skills/commands/hooks 生态丰富，扩展性强。
- 具备会话管理、持续学习、验证与安全等系统化能力。

不足：
- 体系复杂，认知成本较高。
- 能力面很大，若治理策略不清容易出现选择负担。

## 5. 典型场景建议

### 优先选择 ARGO 的场景

- 核心业务链路，错误成本高。
- 多团队协作且需要严格审计和追责。
- 项目处于中后期，架构稳定性优先于短期迭代速度。

### 优先选择 OpenSpec 的场景

- 需求探索频繁，强调快速迭代和低成本协作。
- 团队希望先建立“规格先行”文化，再逐步增强治理。

### 优先选择 SUPERPOWER 的场景

- 希望通过技能自动触发快速提升开发执行效率。
- 团队已有基本工程规范，但缺少自动化执行机制。

### 优先选择 ECC 的场景

- 多语言、多项目并行，且使用多种 agent harness。
- 需要统一的工程操作层和规模化能力池。

## 6. 组合策略建议

在多数真实团队中，单一方案并非最优。推荐采用“分层组合”：

- 用 OpenSpec 处理前期需求澄清与规格组织。
- 用 ARGO 管理关键主链路的架构契约与验收闭环。
- 用 SUPERPOWER 或 ECC 提升执行阶段效率与自动化能力。

可参考的组合路径：
- 轻量团队：OpenSpec + SUPERPOWER
- 成熟团队：ARGO + SUPERPOWER
- 平台型团队：ARGO + ECC
- 大型多业务团队：OpenSpec + ARGO + ECC

## 7. 选型速记（给管理层）

- 如果你最在意“稳定交付、可追溯、可审计”：优先 ARGO。
- 如果你最在意“轻量、快速、低门槛”：优先 OpenSpec。
- 如果你最在意“开发节奏自动化”：优先 SUPERPOWER。
- 如果你最在意“跨平台与规模化能力”：优先 ECC。
